## Vehicle registry sourcing — approval required

- Obtain VCdb/ACES coverage samples and software-provider licensing terms.
- Obtain a CLASSIC.COM historical taxonomy evaluation and licensing terms.
- Define canonical identity, alias normalization, source-evidence, conflict, and verification policies.
- Use vPIC, FuelEconomy.gov, EPA, and other authoritative sources for permitted verification/enrichment.

1. Define service boundaries and versioned schemas alongside the pilot frontend.

3. Add PostgreSQL persistence and an explicit `localStorage` migration/synchronization path.
4. Build a controlled Knowledge Harvester with licensing, provenance, conflict, and reviewer gates.
5. Add staged deployment, database migrations, backups, observability, and rollback.

## Long-term learning relationship

`Vehicle/Chassis -> Installed Engine/Build -> Components -> Baseline -> Diagnosis -> Change -> Retest -> Result/Evidence`

Learning records must preserve Configuration, Baseline, Problem, Change, After Measurement, Result, Evidence, Confidence, and positive/negative/mixed/no-change outcomes.
